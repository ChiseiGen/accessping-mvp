# AccessPing Validation Plan

Last updated: 2026-06-04

## Target Users

Primary:
- Webflow freelancers doing client handoffs
- Shopify agencies running pre-launch QA
- WordPress developers preparing sites for approval
- Small web agencies with multiple client projects
- Solo web builders who need repeatable handoff proof

Secondary:
- Small SaaS product teams before campaign launches
- Project managers checking launch readiness
- Technical leads without dedicated accessibility QA

Anti-persona:
- Enterprise accessibility teams
- Users needing authenticated scans or multi-page crawling
- Users expecting legal compliance certification

## Feedback Questions

### Core validation questions

1. **Problem confirmation**
   - "Walk me through your current pre-handoff QA process."
   - "What takes the most time when preparing client reports?"
   - "Have you ever had a client point out accessibility issues during review?"

2. **Workflow fit**
   - "How would you fit AccessPing into your current process?"
   - "What would need to change for you to save reports regularly?"
   - "When would you open a saved report vs. run a new scan?"

3. **Report quality**
   - "Does the report make sense for a client conversation?"
   - "Is the score meaningful or confusing?"
   - "What would make you trust this report enough to send it to a client?"

4. **Pricing willingness**
   - "What would you pay monthly for unlimited saved reports?"
   - "What would make this worth $19/month?"
   - "What features would justify higher pricing?"

5. **Competitive positioning**
   - "How is this different from [existing tool]?"
   - "What would make you switch from your current approach?"
   - "What is missing that would make this a complete solution?"

### Quick feedback (async)

- "What did you expect vs. what you found?"
- "What was the most surprising part?"
- "What would you cut entirely?"
- "What is missing that you expected to find?"

## Validation Success Criteria

### Strong signal (move toward paid features)

- User runs 3+ scans in a week
- User saves a report and returns to it
- User shares a report link with a colleague
- User mentions this to someone else without prompting
- User asks about bulk pricing or team features
- User reports back that they used the report in a client meeting
- User wants to pay before the product is officially monetized

### Moderate signal (continue validation)

- User completes a scan and saves the report
- User provides specific, actionable feedback on the report format
- User mentions competitor and explains why they'd choose AccessPing
- User engages in 2+ conversations about the product
- User joins the beta/waitlist and responds to follow-up

### Weak signal (pivot or persist)

- User tries once and doesn't return
- User says "interesting" but provides no specific feedback
- User compares only on scanner accuracy, not workflow value
- User says "I'll try this later" but never does
- User asks for features outside MVP scope (auth, bulk, branding)

### Strong objections (understand before proceeding)

- "My clients don't care about accessibility scores"
- "I already use [competitor] and it works fine"
- "The report doesn't feel professional enough for clients"
- "I don't trust automated scans for anything important"
- "This is too much work for a single page check"

## What Counts As Strong Signal

### Conversion indicators
- User pays (even in beta)
- User refers someone else
- User asks about enterprise/agency pricing
- User uses the product without prompting for 2+ weeks
- User provides written testimonial or case study

### Engagement indicators
- User saves 3+ reports
- User opens same report 3+ times
- User exports PDF for a saved report
- User copies shareable link
- User submits feedback form without prompting

### Product-market fit signals
- User asks "when will X be ready?" (X being a feature you planned)
- User reports back on how they used it in a real project
- User finds a use case you didn't anticipate
- User suggests improvements that align with your roadmap

## What Counts As Weak Signal

- User completes onboarding but never returns
- User says "nice" without exploring further
- User compares only on price/accuracy without mentioning workflow
- User asks for features that indicate they're not the target user
- User says "maybe later" without specific blockers

## Next Steps After Validation

1. **Compile feedback** - Categorize responses into themes
2. **Identify patterns** - What do satisfied users have in common?
3. **Prioritize features** - Based on user requests vs. assumptions
4. **Set conversion goal** - Target: 10 paying users or 50 active free users
5. **Plan beta pricing** - Test with small group before public launch
